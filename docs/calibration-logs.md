# 战斗日志逐击校准（2026-10-30）

目的：先把伤害计算器对准，再排轴。标准答案用 zmdlogs 战斗日志（sources/raw/zmdlogs，9 场，逐击伤害、暴击标记、增益的乘区/数值/起止、全队配装含副词条）。工具 `node tools/log_replay.mjs [--detail] [--log 后6位]`。

## 方法
- 面板：按日志 roster 重建（潜能、武器精炼、技能等级、每件装备与精锻），别礼 4 件装备的主副词条逐件与引擎数据一致（纾难手套 力量 111 / 所有技能伤害 31.2%，应龙轻甲 113/75/17.94%，应龙短刃 连携技伤害 53.82%×2）。
- 增益：按日志区间。同 key/来源/目标的区间合并（刷新不叠加）；敌方同名减益（诀与别礼各施加的寒冷脆弱）取最大；同帧施加的增益不作用于同帧命中（见开放问题 1）；攻击增益加到攻击%；攻击药按日志区间同样处理。
- 常驻被动：效果目录里 mode=auto 的伤害区条目（武器常驻、潜能倍率、套装攻击等）。条件型（应龙之锐、玉中身下个连携 +70%、碾骨重压）未加。
- 敌人：解包属性表（防御 100；阿莱克琉斯全抗 20，其余 0）。白刃穿水未拿到表，按防御 100、抗性 0。
- 暴击命中按日志里的暴伤（+50%）折回不暴击；比值 = 日志 / 引擎。
- 只映射能确定对应段的命中：祀战技、汤汤连携、诀破晦阵、别礼幻影 / 斩击 / 层伤 / 终结三段，共 158 击。未映射的大头：祀连携（多段，9.2M）、笔意爆发、汤汤水龙卷跳伤、祀终结跳伤、寒冷爆发。

## 结论
1. 公式骨架成立：祀战技与汤汤连携在干净场误差 ≤4%，这两击身上同时有攻击药、长息增伤、玉中身易伤、肃阵易伤、诀脆弱、祀增幅，说明乘区之间相乘、攻击药加在攻击% 这两条对。
2. 乘区内加算还是乘算，这批数据分不出：把增伤 / 脆弱 / 易伤各自改成乘算或"常驻加算、限时各乘"，按段离散度只差 0.3%。需要更极端的增益组合或训练场对照才能定。
3. 固定残差（干净场也在）：别礼终结 ×1.27–1.30、别礼连携 ×1.10、诀破晦阵 ×1.09。都是引擎偏低，说明漏了常驻项，不是乘区错。别礼终结的候选：低温脆性的读法、未记录的被动；要去测评 / 论坛找。
4. 别礼幻影追击引擎偏高且随场次变（0.56–0.91）。按"主控攻击力结算"检验：隐含攻击力（比值×别礼面板）在诀主控的三场为 3700–5262，诀面板 4633–5713，接近但不一致；祀主控的白刃穿水为 2302–3356，祀面板 6521，不符。结算基数与所吃增益都未定，待查。
5. 账号级偏差：dusk 两场所有干员一致偏高（祀 1.14、别礼终结 1.56），日志没有料理 / 基建类字段，疑有未记录的增益。校准公式时排除这两场。
6. 场次级异常：危境再现·祀（68 s）与白垩界卫 的别礼比值在 0.11–2.0 之间跳，疑 Boss 阶段、失衡、无敌窗口未记录；白刃穿水多目标且敌人表缺失。这三场只做结构参考。

## 开放问题
1. 同帧施加的增益是否作用于同帧命中（祀战技自己施加的玉中身易伤）：算 → 0.93，不算 → 1.06。
2. 落草 / 赫拉芬格 / 肃阵 "两种效果独立生效，且均无法叠加" 的读法：日志显示 赫拉芬格 的 +28%（战技后）与 +56%（连携后）同时在身，按同时计入。
3. 别礼层伤的层数：日志不记附着层数，按低温症 4%×层反推。

## 协议层证据（2026-10-30，来源：开源项目 deepdarkssj/ZMDLogs 仓库里的游戏 protobuf 定义，MIT）
zmdlogs 的客户端是 Npcap 被动抓包：监听游戏客户端与战斗服务器之间的流量，用本机 GameAssembly.dll 的导出函数解密，再按 protobuf 定义解析。仓库 `proto/` 里有 1778 个游戏协议定义，和伤害有关的几条直接说明了结算结构：
- `DAMAGE_PROCESSOR_TYPE`：AttackerCritRate / AttackerAtk / AttackerCritDamage / AttackerPen / DamageScale / DefenderDef / ModifyCalculateResult / InstantModifyAttribute。伤害是一串处理器依次作用。
- `DAMAGE_SCALE_PROCESSOR { damage_scale_side, zone_name, addition }`：增益对伤害的作用是"往某个命名乘区加一个值"。日志里的 dmg_inc / amp / fragile / vuln_taken / prod_vuln_taken 就是 zone_name。所以"乘区之间相乘、区内加算"是数据定义层面的结构，不是社区猜的；prod_ 前缀的区是另一类，只见于 Boss 被动和失衡。
- `ATK_CALCULATION_TYPE`：AtkScale（攻击×倍率）/ DefiniteValue（固定值）/ MultiplyAttribute（某属性×倍率+加值）/ BreakingAtkCalc / PrimaryAttrCalc。目录里"固定伤害""按防御力倍率""记录伤害"这些路径对应前三种。
- `BUFF_RES`：每个 buff 带 `attr_modifiers`、`damage_modifiers`、`stacking_settings { stacking_type, stacking_key, max_stack_cnt, priority }`、`duration`。同名能否叠加、取大还是取新，是每个 buff 自己的字段。
- `BATTLE_DAMAGE_DETAIL`：每一击带 value、is_crit、attacker_modifiers / defender_modifiers（作用于这一击的 buff 句柄）。
- `SKILL_COST_TYPE`：SkillCostUltSp（终结技能量）/ SkillCostAtb（技力）。`BATTLE_ATB_DATA { atb_value, atb_recovery_speed, client_tick_ts, reason }`、`BATTLE_UPDATE_ATB_INFO_OP_DATA { delta_value, template_id }`：技力当前值、自然回复速度、每次变化量和来源都在包里。
- `BATTLE_SKILL_START_CAST_OP_DATA` / `END_CAST`：施放开始、结束各一条，带时间戳。

意义：假设清单里"时序"一节（施放时间、普攻段时长、终结技演出）和"技力经济"一节（自然回复、重击回技、能量）都能从抓包得到精确值，不用逐帧看视频。zmdlogs.com 网页只展示了其中一部分（伤害与增益），技力、能量、施放窗口在原始包里但没上网页。


## 整条轴复现（2026-10-30，tools/log_sim_replay.mjs）
把日志的施放序列（有施放标记的用标记时刻；没有的按首击时刻减去解包命中帧回推）喂给模拟器（`timingSource:'akedata'`，不可行时最多顺延 6 s），两侧都按"施放簇"归并后按顺序配对，逐次对比技能伤害（不含普攻与机制伤害）。

### 这轮解开的
- 别礼幻影追击：解包 buff_…_phantom 有两个伤害单元各 @atk_scale，normal_skill 时间线第 0 帧把 atk_scale 乘 0.5 → 两跳各 160%，合计 320%；日志记两跳。之前"引擎偏高 75%"是拿一跳对 320% 造成的。
- 汤汤战技：射击 = 27–39 帧每 0.033 s 共 5 跳 × 36%（180%）；每个水龙卷 = 90 帧内每 0.26 s 一跳、每目标最多 11 跳，合计 300%；总量与模拟一致。
- 祀连携：10 跳各 40%（14–43 帧）+ 终击 350% + 100%×层数（49 帧），潜 5 五个倍率键各 ×1.15、层数 +1。9 场日志终击/跳伤比值反推层数：15 次里 11 次正好 4（潜 1/2）或 5（潜 5），2 次是 7.7 / 11.6——都是墨龙在场那一秒队友又上了附着。按"吸收"建模（mechanics.combo.absorb，提交 ca93554）。

### 还没对上的（按日志伤害占比排序）
1. 祀连携的时序：ed2ab0 施放标记 7.17 s，但十跳落在 9.17–10.05 s，正好在祀终结技（9.06）之后；模拟器按标记时刻放，墨龙 7.64–8.8 s 在场，吸不到 9.76 s 汤汤上的附着。标记与首击差 2 s 的原因未知（切人入场？排队？），日志里其他连携没有标记可比。
2. 祀战技链：日志四次标记全是 normal_skill（河山共影），笔意爆发在 9.69 与 22.87 那两次之后约 1 s 出现；解包里 笔意（inkhurteffect，同目标最多 1 个）被重新施加时旧的结束并引爆，但 17.03 那次没有爆发记录。日志的施放标记分不清 河山共影 / 起墨 / 收笔（三者是否都记成 normal_skill 未知）。模拟器按三段替换走，第二次放的是起墨，17.03 那次既无伤害也不上附着，导致诀连携、别礼第二次连携在模拟里放不出来（连锁）。
3. 别礼第二次连携：日志 19.75 s 消耗 3 层（脆弱 0.12），来源是汤汤战技 9.76、祀战技 17.03、诀连携 17.89；模拟里祀那次没上附着（见 2）。
4. 诀：日志只记"重要"命中（囹圄爆炸、破晦阵生成），集束打击没有记录，诀的 2.5 万无法对比；模拟 7.9 万。

### 复现工具里的常数（都不是模拟参数，只用于把日志命中归到施放）
同一次施放相邻命中最大间隔 1.5 s（解包多段技能段间最长 0.97 s）；子实体跳伤归并窗：水龙卷 8 s、幻影 16 s、囹圄 8 s、笔意 25 s（各自解包存活时长加余量）；施放标记只认首击前 4 s 内（解包施放到首击最长 2.87 s 加切人余量）。

### 两条时序事实（2026-10-30，从日志得到）
- **日志的计时在终结技演出期间不走。** 别礼连携首击后 0.06 s 就记到终结技首击（b83e60 38.09→38.15；骏卫 0.12 s 两次；管理员 0.21 s），而解包里别礼终结技首击在第 86 帧、演出到第 85 帧——首击在演出结束后一帧。祀终结技标记到首跳 0.10–0.28 s，等于首跳帧 63 减演出 58 帧。所以日志时间 = 真实时间减去所有演出时长。复现工具把每次终结技之后的施放时刻加上该终结技的演出时长再喂给模拟器。
- **终结技不受施放者自身动作的忙碌限制。** 解包全部 790 个干员技能文件里，AllowNext 列表没有一个含终结技；日志里连携首击后 0.06–0.21 s 即有终结技首击。引擎据此去掉了终结技施放时的"正在执行其他动作"检查（演出中仍然不能放）。

加上这两条后 ed2ab0 的复现：别礼 0.96、汤汤 1.23、祀 0.38、合计 0.71（之前 0.59）。祀剩下的差距在连携终击的吸收层数（日志按增益差校正后约 9 层 = 4 消耗 + 潜 5 + 墨龙在场时汤汤水龙卷 4 跳各吸收 1 层；模拟里汤汤战技只上 1 次附着）。
