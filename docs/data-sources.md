## 2. 两个来源是否独立

- **官方 wiki 由人工录入游戏内显示值。** 证据是页面里有大量人为错误，解包数据里没有这些错误：小数点写成逗号（“1,5”）；数字抄错（566% 应为 556%）；精锻数值按“初始值 + k×取整后的步长”等差外推，而不是游戏实际用的乘法；技能名错字（“攻击提示·大”）；同一句话重复（“3件套组效果：3件套组效果：”）。
- **华法琳是游戏数据表解包。** 证据是数值保留了未取整的浮点数（如 `phydam: 0.044444446`、全伤害减免 `0.8285004`），描述是带 `{key:0.0%}` 占位符的模板，加上 blackboard 参数，还有游戏内部的条件字段（如 `lizhiyan_wisd`）。
- **两者没有互相抄录。** 官方的录入错误没有出现在解包数据中。反过来，解包的显示文本错误（艾维文娜连携技 subDesc 写“获得终结技能量 0”）也没有出现在官方页面。两边的源头都是同一款游戏，所以一致说明数值可信，不一致则来自录入或显示文本错误。

### 3.1 本次对核对脚本和解析器的修正

- `tools/crosscheck.mjs`（重写）：
  - 技力消耗、所需终结技能量（含噗切娜的“消耗技力 / 消耗能量”）、冷却时间分别改为与 `cost.value` 和 `coolDown` 比较。
  - 技能按 `skillGroupMap` 定位：先按名称匹配，名称不同时按技能类型匹配。数据行只在本技能组内查找。
  - 行名称容许“的 / 第 / (秒)”这类差异，并用字符相似度兜底。
  - 诀的阵诀·智 / 意按描述首行识别，再筛选 subDesc 的 `cond`。智模式的冷却时间要加上天赋修正：`potentialTalentEffectTable` 中 `skillParamModifier`，paramType 2 = coolDown，值为 −6。
  - 武器技能按槽位配对，并用 blackboard 渲染模板。支持格式 `0` / `0.0` / `0.00` / `0%` / `0.0%`，以及表达式占位符（如 `{1-dmg_taken_down:0%}`、`{spell_dmg_up2*max_stack:0.0%}`）。
  - 装备属性按“官方属性名 → 游戏 packAttrType”配对，因为非金色装备官方列出的顺序与游戏表不同。逐值记录哪条取整规则成立，按属性类型统计主规则，并区分“取整例外”和“冲突”。没有精锻表的非金色装备也核对初始值。新增套装效果比较。
- `tools/parse_warfarin.mjs`：装备的 `skillPatchTable` 不像干员 / 武器那样按 skillId 分键，而是直接一个 bundle。原解析把 228 件装备的套装技能全部解析成空。已修正并重跑。
- `tools/parse_skland.mjs`：
  - 3 星武器的技能表在两个技能之间有一个空列。原解析把它当成第 2 个技能，导致塔尔11、达尔霍夫7、奥佩罗77、佩科5、吉米尼12 的技能错位，旧报告显示为 `no-mined-skill`。现在丢弃空列。
  - 同一技能表里重复的行名会被覆盖。梨诺终结技有两行“每点敏捷增加的治疗值”，第一行（0.76–1.7）丢失。现在把重复行保留为 `label#2`。
  - 重跑后，`operators/gear/items/substrate` 中除梨诺这一行外没有其他变化；`weapons.json` 只有上述 5 把武器变化。

## 5. 取整规律（以数据为证）

| 数据 | 规律 | 证据 |
|---|---|---|
| 干员属性（生命、攻击、四维） | 显示值 = 内部值**向下取整** | 1224 个全部满足；其中 427 个用四舍五入会出错 |
| 装备基础防御力 | **向下取整** | 内部有小数的 37 个值全部满足 floor，其中 27 个用四舍五入会出错（如 16.8 → 16） |
| 装备四维属性 / 主能力 / 副能力（整数值） | 内部即整数，直接显示；精锻值 = floor(初始值 × (1+0.1k)) | 解包不变量 1581/1581 |
| 装备源石技艺强度 | **向下取整到整数**（内部为小数，如 20.7 → 20、45.54 → 45） | 100/102 满足 floor，round 只满足 24 个；另 2 个是险关手甲的冲突 |
| 低阶装备固定攻击力 / 生命值（平值） | 攻击力向下取整；生命值两种规则都能解释，无法区分 | 攻击力 floor 4/4，round 2/4；生命值 6 个值 floor 和 round 都命中 |
| 装备百分比属性（伤害加成、暴击率、充能效率、治疗效率、攻击力% / 生命值%、主 / 副能力% 等） | **四舍五入到 1 位小数** | 每种属性类型的主规则都是 round1（如连携技 70/76，剩余 6 个全是冲突或例外；终结技伤害 35/35）；floor1 明显更低（如 17/35），可排除截断 |
| 装备全伤害减免 | 内部存**受伤倍率 x = 1/(1+d)**，显示为 (1−x) × 100 四舍五入 1 位 | 13/14 满足，另 1 个是 x.x5 边界例外 |
| 武器技能百分比（`{key:0.0%}`） | **四舍五入到 1 位小数** | 2106 个占位符中有 156 个 floor 与 round 结果不同，官方全部与 round 一致 |
| 武器 / 套装模板中的 `{key:0%}` | 四舍五入到整数 | 套装 25 套一致；壤流、清波官方额外多写了“.0” |
| 干员技能 subDesc 百分比 | 与 blackboard × 100 按官方显示位数四舍五入一致 | 普攻 218/220。卡缪 0.385 → 39%、0.655 → 66% 说明是四舍五入（half-up） |

普攻 blackboard 的注意点：
- 显示用的倍率键名不统一，有 `display_atk_scale`、`atk_scale_display`、`atk_scale` 三种。
- 萤石普攻第四段显示的是单段 `atk_scale`（60%），`display_atk_scale` 是 3 段合计（180%）。
- 黎风普攻第三段显示 `atk_scale` 35%，而 `display_atk_scale` 为 34%。这一处原因待查。
- 计算时应使用实际的分段 `atk_scale*` 键和段数，不要直接用显示倍率。
